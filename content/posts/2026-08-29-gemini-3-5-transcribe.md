## 왜 지금 이 주제인가

Google이 8월 26일 음성 인식 모델 Gemini 3.5 Transcribe를 Gemini API 공개 프리뷰로 내놨습니다. 성능 수치보다 먼저 눈에 들어오는 것은 이름입니다. Google의 기존 음성 인식 계열은 Chirp였는데, 이번 모델은 Chirp 4가 아니라 Gemini라는 이름을 달고 나왔습니다. 음성 인식을 별도 기술 스택으로 두지 않고 언어 모델 제품군 안으로 흡수하겠다는 결정에 가깝습니다. 발표문도 이 모델을 "소리를 글자로 옮기는 도구"가 아니라 "정돈된 텍스트를 만들어 내는 모델"로 설명합니다.

## 공개된 내용

Gemini 3.5 Transcribe는 두 벌로 나뉩니다. 녹음된 오디오를 처리하는 gemini-3.5-transcribe는 Interactions API로, 실시간 오디오를 다루는 gemini-3.5-transcribe-live는 Live API로 호출합니다. 실시간 쪽은 양방향 세션을 유지하며 1초 미만 지연을 목표로 한다고 밝혔습니다.

Google이 내놓은 수치는 이렇습니다. Artificial Analysis 측정 기준 단어 오류율(WER, word error rate)은 사전 녹음 오디오에서 2.6%, 실시간 스트리밍에서 4.0%입니다. 다국어 벤치마크인 FLEURS에서는 비스트리밍 5.04%, 스트리밍 5.50%를 기록했습니다. 최종 전사가 확정되기까지 걸리는 시간은 이전 모델 Chirp 3 대비 70% 줄었다고 설명합니다. 언어는 85개 이상을 자동으로 감지해 처리합니다.

Google이 강조하는 지점은 오류율보다 출력물의 형태입니다. 배경 소음이 섞이거나 전문 용어가 나오거나 말이 끊기는 상황에서, 기존 인식 모델이 들리는 대로 받아 적었다면 이 모델은 그 결과를 다듬은 상태로 내놓습니다. 어, 그러니까 같은 군더더기 말을 걸러 내고, 말하는 도중 스스로 정정한 부분을 반영하고, 문장 부호와 문단을 붙이는 작업까지 한 번에 처리한다는 설명입니다.

기능 쪽에서는 화자 구분과 단어 단위 타임스탬프가 별도 옵션이 아니라 기본 모델에 들어가 있습니다. 화자는 세 명까지 지원하고 그 이상은 실험 단계로 표시돼 있습니다. 고유명사나 전문 용어를 미리 등록하는 커스텀 어휘도 제공합니다. 특이한 항목은 함수 호출입니다. 전사 모델이 작업 일부를 다른 Gemini 모델에 넘길 수 있게 설계돼 있습니다.

가격은 Gemini API 문서에 공개돼 있습니다. 녹음 모델은 오디오 입력이 분당 0.003달러, 텍스트 출력이 분당 0.002달러입니다. 실시간 모델은 오디오 입력 분당 0.005달러, 텍스트 출력 분당 0.004달러입니다. Google은 오디오 입력을 초당 25토큰, 텍스트 출력을 분당 175토큰으로 환산해 이 분당 요금을 산출했다고 밝혔습니다. 무료 티어에서는 요금이 발생하지 않습니다.

이미 여러 제품에 들어가 있습니다. Android Gboard의 Rambler, macOS용 Gemini 앱, 개발 환경 Antigravity의 프롬프트 입력창 마이크가 이 모델을 씁니다. Chrome의 웹 입력란 음성 입력은 예정 단계입니다. 기업 쪽은 Gemini Enterprise Agent Platform에서 프리뷰로 쓸 수 있고, 고객 응대용 제품에도 들어갈 예정이라고 밝혔습니다. 외부에서는 실시간 음성 애플리케이션을 만드는 데 쓰이는 Agora, LiveKit, Pipecat, Fishjam과 LangChain, Vercel 등이 연동 대상으로 함께 언급됐습니다.

## 의미와 한계

가장 실질적인 변화는 후처리 파이프라인이 사라진다는 점입니다. 지금까지 음성을 업무에 쓰려면 인식 모델이 뱉은 원시 전사를 받아 군더더기 말을 지우고, 말하다 고친 부분을 정리하고, 문단과 문장 부호를 붙이는 별도 단계를 붙여야 했습니다. 이 작업을 다시 언어 모델에 맡기는 2단 구조가 흔했습니다. Gemini 3.5 Transcribe는 그 단계를 모델 안으로 넣었습니다. 화자 구분과 타임스탬프가 기본 제공에 포함된 것도 같은 방향입니다.

한계도 분명합니다. 우선 공개 프리뷰라 안정성과 가격이 확정된 상태가 아닙니다. 오류율 수치는 85개 이상 언어를 아우른 평균값이라 개별 언어, 특히 한국어에서 어느 정도인지는 이 발표만으로 알 수 없습니다. FLEURS 점수가 종합 WER보다 두 배 가까이 높다는 사실 자체가 언어별 편차를 시사합니다. 화자 세 명 초과 지원이 실험 단계로 남아 있어 회의록처럼 참석자가 많은 용도에는 아직 이릅니다.

정리 기능이 항상 이득인지도 따져 볼 문제입니다. 이건 추측입니다만, 발화를 그대로 남겨야 하는 기록물에서는 모델이 알아서 문장을 다듬는 동작이 오히려 위험 요소가 될 수 있습니다. 무엇을 군더더기로 판단해 지웠는지가 결과물에 남지 않기 때문입니다.

## 한 줄 정리

음성 인식이 독립된 기술 계열에서 언어 모델의 한 기능으로 옮겨 가는 과정을, Google이 모델 이름과 가격표로 분명히 한 발표입니다.
